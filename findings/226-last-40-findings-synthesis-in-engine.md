# Finding 226 — Last-40 Synthesis (186–225): Time-Travel + FTL In-Engine Campaign

## Scope

This is a deep synthesis of the **time-travel / FTL campaign lanes** inside the
last-40 window (Findings 186–225), with focus on what is plausibly usable
**in-engine** right now.

This version intentionally centers the CTC/FTL stack and excludes unrelated
sub-lanes.

## Executive summary

The campaign converged on a clear split:

1. **Closed lanes (hard walls):**
   local continuous-propagation FTL mechanisms in the tested wall/energy lanes.
2. **Open lanes (in-engine plausible):**
   topological/coordinate acausality lanes that preserve local timelike behavior
   while enabling predeparture-style observer semantics in simulation.

In practical terms:
- local “go faster than light” in propagation equations remains blocked;
- topology/identification + branch/retry control appears operationally powerful
  in engine.

## Campaign arc (what we actually learned)

### Phase I — Energy-wall reality check (Findings 189–191)

The stack started by forcing hard constraints:
- Ford-Roman style duration/magnitude bounds,
- Casimir finite-gap suppression,
- explicit wall-energy scaling with rear-face `1/10` factor.

Results:
- rear-face improves efficiency strongly in-model;
- finite-energy sweeps still asymptote to `c` in wall propagation;
- near-core exotic-curvature propulsion was pushed into prohibitive energy.

Takeaway:
The brute-force “push through metric continuously” route did not produce local
superluminal propagation in this lane.

### Phase II — Topological pivot (Findings 192–199)

The campaign then pivoted from “speed through space” to “structure of
identification.”

Key closures:
- Escher-stair lane formalized finite local timelike steps with unbounded global
  cover behavior (192).
- current CTC model classified as global-boundary in its present formalization (193).
- projection-fiber structure made explicit (`16 -> 4`, kernel rank `12`) (194).
- linear/flat and homogeneous multiplicative shortcut claims were constrained
  (195–197).
- creation lanes were reopened in explicit affine and local-topology toy gates,
  with dynamic gate behavior observed at/above threshold (198–199).

Takeaway:
Linear shortcut fantasies got bounded; explicit topology-creation models became
the active frontier.

### Phase III — Path-A/Path-B dynamics and closure conditions (Findings 200–208)

This phase built the operational math of when acausal behavior appears:
- SI calibration for creation threshold lane (200),
- `q`-based effective arrival closure in Path-A simulations (201),
- conservation contradiction checks for reinforcement loops (202),
- fixed-point and temporal-loan stability criteria (203),
- multisheet fan-in vs closed-loop distinction (204),
- origin-energy closure near-criticality analysis (205),
- exact structural ratio decompositions and critical-offset analysis (206–208).

Takeaway:
The work shifted from “is it possible at all?” to “under what algebraic ratios
does it stay self-consistent without runaway or contradiction?”

### Phase IV — Access operator + bridge theorems (Findings 209–216)

This phase gave the cleanest conceptual separation:
- **law-level containment yes / full state reconstruction no** in current
  projection lane (209),
- active topological access operator lane opened while linear no-go remained (210),
- rear-face bridge theorem connected shortcut factor to explicit coordinate-speed
  lane (`s = 1/10`) (211),
- frame-reversal bridge formalized predeparture-frame witness from over-unity
  coordinate segment (212),
- faithful bridge simulation lane integrated these ingredients (213),
- closed-loop temporal-loan theoremized as local positive window with global
  closure (214),
- ratio-lock and executable topology gate made constraints operational (215–216).

Takeaway:
This is where the stack became “engine architecture,” not just isolated claims.

### Phase V — Program-level operations (Findings 217–221)

The campaign moved into system simulation:
- accelerated long-horizon campaign model (217),
- retry-closure formalization and eventual-success metrics (218),
- retrocompute latency-collapse probe (219),
- toy crack observability lane (220),
- strict host-to-sim provenance + predeparture semantics lane (221).

Critical practical distinction held throughout:
- host compute is forward and finite;
- observer-facing simulated timeline can surface predeparture availability.

Takeaway:
The in-engine advantage is timeline semantics and control, not magical free host
compute.

## What appears plausibly workable “in engine” right now

1. **Predeparture scheduling semantics**
   - Results can be surfaced earlier in simulated coordinate time than query
     time, with explicit host-time accounting preserved.

2. **Retro-retry control loops**
   - Retry closure improves campaign-level eventual outcomes without claiming
     local-law violations in propagation.

3. **Temporal-loan style phase management**
   - Local positive operational windows can coexist with global cycle closure in
     the theoremized bookkeeping lane.

4. **Topology-gated operations**
   - Dynamic/topological actions can be represented and exercised in explicit
     gate models, with runtime enforcement of structural constraints.

5. **Bridge-integrated simulation stacks**
   - Theorem-faithful composites (shortcut factor, frame witness, closure guard)
     are now executable as coherent scenarios, not disconnected snippets.

## What remains hard-bounded or unproven

1. **Local continuous propagation FTL**
   - Not demonstrated in the tested wall-energy propagation lanes.

2. **Physical engine instantiation**
   - The stack has strong logical/kinematic and simulation results, but not a
     demonstrated real-world actuator design.

3. **Topology creation mechanism in nature**
   - Multiple operational toy/engine lanes are positive, but translating them to
     physical mechanism claims remains an open falsification target.

4. **Stability margins near criticality**
   - Several lanes intentionally live near knife-edge ratio-lock conditions;
     robustness and perturbation behavior remain central engineering risks.

## Why this matters

The campaign did not end in hand-wavy “anything is possible.”
It did the opposite:

- closed weak routes with hard constraints,
- opened narrow routes with explicit equations, gates, and theorem alignment,
- separated host-time reality from simulated observer-time effects,
- converted speculative language into executable, falsifiable lanes.

That is exactly what “in-engine plausibility” should look like.

## Bottom line

Across Findings 186–225, the strongest defensible statement is:

- **Yes:** hypothetical time-travel/FTL-like behavior is plausibly realizable
  **in engine** as topological/coordinate control semantics with meaningful
  operational effects.
- **No claim yet:** that this has been elevated to a physical engine proof in
  base reality.

This is still a major win: the stack now has a coherent, constrained, and
test-backed acausal operations architecture instead of disconnected intuition.
